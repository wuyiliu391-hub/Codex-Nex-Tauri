## 1. 一句话定位

把 **Codex-Nex**（Go + Wails 的桌面壳）重写成 **Tauri v2 桌面壳 + 官方 codex-rust v0.154.0 引擎**，
目标是在 Windows 上复刻官方 Codex 桌面端的 UI 与交互（1:1 视觉/行为对齐），同时把 Agent 引擎整体外包给官方二进制。

前端不是重写，是**移植**：沿用 Codex-Nex 的 Vanilla JS UI，只把 IPC 层从 `window.go.main.App` 换成 Tauri `invoke`。

## 2. 四层架构与职责边界

```
frontend/src (Vanilla JS, ES module, 无构建器)
   ↓ bridge.js  —— 156 个 App 方法的适配层
src-tauri (Rust, Tauri v2, 无边框窗)
   ↓ WebSocket JSON-RPC ws://127.0.0.1:17457
codex-app-server.exe (官方 sidecar 二进制, 由 Rust 拉起)
   ↓
src/backend (官方 codex-rs 100+ crate 源码，默认不编译)
```

| 层 | 位置 | 职责 | 是否必须 |
|---|---|---|---|
| 前端 | `frontend/src` | 全部 UI；只认 `invoke` 和 Tauri event | 必须 |
| Rust 壳 | `src-tauri/src` | 本地 store（设置/宠物/日历/cinema/连接器/文件树/定时任务）+ 引擎 RPC 转发 + 事件扇出 + 原生菜单 | 必须 |
| 引擎 | `codex-app-server.exe`（外部二进制） | Agent 循环、tools、MCP、skills、plugins、rollout、sandbox | 必须（缺失则降级） |
| 官方源码 | `src/backend/**` | 仅供 `feature = "in-process"` 时进程内链接；**默认 `default = []`，不参与构建** | 可选 |

**关键设计决策（务必守住）**：不把官方 100+ crate 链进 Tauri。
理由写在 `MIGRATION.md` §1 / `docs/RUST_BACKEND.md`：编译时间爆炸、CI 缓存失效、官方任何破坏性变更都会炸壳。
因此壳与引擎通过 **JSON-RPC 协议**解耦 —— 换引擎只要换二进制，不动壳。

## 4. 关键契约（改代码前必读）

### 4.1 握手不可省

```
1. → {"id":"initialize","method":"initialize","params":{clientInfo,capabilities}}
2. ← {userAgent, codexHome, platformFamily, platformOs}
3. → {"method":"initialized"}          ← 无 params 字段，少这一步后续方法全被拒
```
实现在 `client.rs::perform_initialize`，超时 10s；普通请求超时 120s。

### 4.2 方法名是「踩坑重灾区」

官方 v0.154.0 与直觉命名不一致，`protocol.rs` 已固化常量，**不要凭记忆写**：

| 想当然 | 实际 |
|---|---|
| `thread/timeline` | `thread/timeline/list` |
| `config/get` / `config/update` | `config/read` / `config/value/write` / `config/batchWrite` |
| `mcp/listServers` | `mcpServerStatus/list` |
| `shell/open` | `command/exec` |
| `plugin/setEnabled` | 无 —— 只能 `plugin/install` / `plugin/uninstall` |
| `approval/respond` | **不存在** —— 直接回复 server request id 的 JSON-RPC result |

### 4.3 审批是 server→client request，不是 notification

`item/commandExecution/requestApproval` 等到达时，**回 result 对象**给同一个 id：
`{"decision":"accept"|"decline"|"cancel"|"acceptForSession"}`。
前端 `resolve_approval(requestId, approved, kind, sessionScope)` 走 `EngineHandle::respond`。
Esc/点遮罩也必须回 `decline`，否则 turn 挂死（规格文档已明确标注）。

### 4.4 响应形状必须归一化

官方返回形状与旧 Go 后端不同，`bridge.js` 里有一层 extract* 归一化：

- `thread/list` → `{data:[...], nextCursor, backwardsCursor}`（不是 `{threads:[]}`）
- `thread/read` → `{thread:{...}}`（`get_session` 已 unwrap）
- `thread/start` → `{thread, model, modelProvider, cwd}`（`new_session` 已摊平 thread 并保留 `threadStart`）
- `mcpServerStatus/list` → `{data:[...]}`
- `turn/start` params 是 `{threadId, input: UserInput[]}`，UserInput = `{type:"text", text}` —— **不是** `{input:{items:[]}}`

### 4.5 事件命名有硬约束

Tauri event 名不允许 `.`，所以 Rust 侧把 `turn/completed` → `codex:turn-completed`（`/` 和 `.` 都换成 `-`）。
`bridge.js` 再把它映射成前端 `agent:*` CustomEvent。
**注意**：`bridge.js` 的 `codexToAgent` 表里同时列了 `codex:turn.completed`（点）和 `codex:turn-started`（横杠）两种写法，而 `onCodexEvent` 会把非法字符替换成 `-`，所以两套写法最终都落到同一个 channel —— 能跑，但是历史遗留，接手后建议统一成横杠一种，别再加点号别名。

### 4.6 引擎离线必须降级

所有引擎调用走 `Promise.allSettled`，失败返回空数组。
`compositeGetState()` 把本地 store + 引擎数据合成 `bootstrap.js` 期望的单一快照。
**没有 sidecar 二进制时窗口照样能开**，只是 `engine_status.connected=false`、列表全空。

## 9. 2026-09-17 修复记录（本轮）

触发原因：设置 → 自定义供应商 → 「运行检查」报
`connect codex-app-server: IO error: 由于目标计算机积极拒绝，无法连接。(os error 10061)`

### 根因：三个故障叠在同一条路径上

只修一个都不会恢复引擎 —— 这是本轮最重要的结论。

1. **没有二进制**。`resolve_sidecar_source` 的 5 条解析分支全部落空 → `bin.exists()` 为假 → **静默不 spawn**。
2. **spawn 参数错误**。`start()` 无条件传 `--session-source codex-desktop`，而实际发的
   `codex-cli 0.154.0-alpha.6.2` **没有这个参数** —— clap 报
   `error: unexpected argument` 后立即退出，端口永不监听。
   （旧文档 `RUST_BACKEND.md` 声称有该参数，那是照源码树写的，发布版没有。）
3. **二进制形态不匹配**。官方桌面端发的是**多合一 `codex.exe`**，需要 `app-server` 子命令；
   代码假设的是独立 `codex-app-server.exe`。

### 顺带修掉的另外两个缺陷

4. **首次连接无重试**。`EngineHandle::rpc` 只连一次，跟 sidecar 启动赛跑。
5. **「运行检查」是空转**。实测 `model/list` **完全忽略 `providerId`**，返回静态目录；
   且 `bridge.js` 丢掉 8 个参数里的 7 个，参数名与 `settings.js` 的调用顺序还错位。
