入口 `app/main.tsx` 在渲染前安装路由、启动事件桥并加载偏好/语言，随后挂载 `<App>`；`App.tsx` 仅负责把协议通知（`onNotification`）和服务器请求（`onServerRequest`）写入 `turnStore`/`notificationReducer`，再渲染 `AppShell`。

- 视图层：`shell/AppShell.tsx` 作为外壳容器，组合 `TitleBar`、`Sidebar`、`main#main` 中的 `ViewHost`（Home/Discovery），以及兄弟节点 `SettingsShell`，严格保持与旧版 `shell.css` 约定的 DOM 结构（`.sidebar`、`.main`、`body.settings-open` 等）。
- 状态层：`state/appStore.ts` 使用 `useSyncExternalStore` 暴露一个全局 `AppState`（sessions/projects/providers/settings/engineStatus），所有数据来自后端 `invoke`，无本地种子；`turnStore`、`preferencesStore`、`appearance`、`notificationReducer` 各自管理独立切片。
- 协议桥：`bridge/events.ts` 是唯一的后端消息入口，按 `@protocol/notifications` 中生成的方法表自动订阅所有通知通道，并以 `codex:method` 形式映射到 Tauri event；服务器请求走固定通道 `codex:approval`、`codex:user-input`。
- 开发模式隔离：`vite.config.ts` 在 `--mode browser` 下用别名将 `@tauri-apps/api/core|event` 指向 `devbridge/tauri-core.ts`、`devbridge/tauri-event.ts`，并通过自定义插件把 `/appserver` WebSocket 代理到 `CODEX_APP_SERVER_WS` 指向的真实引擎，使浏览器也能调试 shell 命令表面。
- 资源复用：构建产物输出到 `dist/`，CSS/字体/pet 精灵等资源仍从 `src/styles`、`src/assets` 静态引入，保证与官方外观 1:1 兼容。
- 依赖方向：views → shell → state → bridge → @protocol；state 反向通过 `invoke` 调用 Rust 命令，不直接依赖 Tauri 以外的运行时。
