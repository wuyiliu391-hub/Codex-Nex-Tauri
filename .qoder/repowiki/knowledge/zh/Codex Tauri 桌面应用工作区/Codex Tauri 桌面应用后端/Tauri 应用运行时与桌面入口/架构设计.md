模块由四个文件构成 Tauri 应用的运行时骨架：`main.rs` 仅作为 Windows GUI 入口（通过 `windows_subsystem = "windows"` 隐藏控制台），调用 `codex_tauri_lib::run()`；`lib.rs` 是真正的启动核心，初始化 `tracing_subscriber` 日志、注册 `tauri_plugin_dialog/shell/fs/store` 等插件、挂载 `menu` 与 `on_menu_event` 处理器，并在 `setup` 中按顺序完成三件事——加载 `state::AppState`、创建并管理 `codex::ProtocolAdapter`（将配置中的 provider 路由到本地端口）、启动 `codex::EngineHandle` 侧进程并通过 `events::spawn_event_bridge` 把 sidecar 通知转发为前端事件，最后用 `tauri::generate_handler!` 集中注册所有 IPC 命令（app_state/settings/pets/calendar/cinema/connectors/fs/scheduled/market/engine 等）。`state.rs` 提供 UI 层的状态模型（Settings/Preferences/Pet/CalendarEvent/CinemaTimeline/Connector/Shortcut/ScheduledTask 等）与 `AppState` 单例，使用 `Mutex<InnerState>` 保护内存态，并以原子写入（先写 `.tmp` 再 `rename`）的方式持久化为 `shell-state.json`，默认数据目录位于 `dirs::config_dir()/CodexDesktop`。`menu.rs` 通过 Tauri 原生 `Menu/Submenu/MenuItem` 构建 File/Edit/View/Help 四栏菜单，并将点击事件以 `menu` 事件名 + action id 字符串的形式 emit 给前端，实现菜单逻辑与 UI 解耦。依赖方向单向：`main.rs` → `lib.rs` → (`state.rs`, `menu.rs`, `commands::*`, `codex::*`)，状态与命令之间无直接耦合，均通过 Tauri 的 `AppHandle`/`Manager` 共享。
