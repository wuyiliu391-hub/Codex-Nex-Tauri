feat(kernel): wire the audited frontend contracts into the backend

Four independent audits of the frontend found 16 places where the desktop
kernel and the UI disagreed about a payload. Every one of them failed
*silently*: the call succeeded, the field was simply never there. This closes
all of them, plus the two contract gaps the kernel could not have filled
without new state.

Settings were being discarded on every save
-------------------------------------------
`Settings` had seven named fields and no `#[serde(flatten)] extra`, while the
frontend sends one flat object carrying `sidebarCollapsed`,
`activeProjectPath`, `fullAccess`, `webSearch`, `outputVerbosity`,
`reasoningSummary` and `modelReasoningEffort`. Serde ignored the unknown keys,
and because `save_settings` replaced the whole struct, each save erased them —
then `get_settings` handed the UI back an object missing them. `Preferences`
already had the flatten; `Settings` now matches it.

Two things the flatten exposes are handled explicitly:

  * `save_settings` merges `theme` and `terminal_shell` forward. Nothing in the
    current UI writes either, so a wholesale replace would blank a value set by
    hand in shell-state.json on the first unrelated toggle.
  * `normalise_keys()` drops the camelCase copies the frontend dual-writes, and
    collapses `active_project_path` onto `activeProjectPath`, so the file does
    not grow on every save and no setting has two sources of truth.

Token usage could never render the context badge
------------------------------------------------
The reducer reads six counters; the kernel sent three. `Composer.tsx:955-973`
gates the context-usage percentage on `modelContextWindow > 0`, so that badge
was unreachable, and the cached/reasoning counters were always blank.
`ProviderChunk::Usage` now carries `cached_input_tokens`,
`reasoning_output_tokens` and `model_context_window`, each decoded from where
its protocol actually reports it:

  * OpenAI chat: `prompt_tokens_details.cached_tokens`,
    `completion_tokens_details.reasoning_tokens`, plus a top-level
    `model_context_window` some gateways add.
  * Responses API: the same detail keys, window on `/response`.
  * Anthropic: `cache_read_input_tokens`, `output_tokens_details.thinking_tokens`.
  * Ollama states none of them.

Each stays `None` when the provider did not report it and is omitted from the
event, so "unknown" is never rendered as a fabricated zero. The echo provider
reports all three as unknown rather than inventing a window.

Threads had no working directory
--------------------------------
`new_session` ignored the `projectPath` the composer sends, and neither
`list_sessions` nor `get_session` returned a `cwd`. The sidebar derives its
project list from the distinct `cwd` values of loaded threads
(`appStore.ts:216-225`), so the project list was permanently empty and every
thread was project-less. `Thread` now carries `cwd`, `create_thread_in` records
it, and all three commands return it.

Other contract fixes
--------------------
  * `list_providers` now emits `name`, `hasApiKey` and `realBaseUrl`, which is
    what `normaliseProviders` reads. Without them no provider showed its key
    badge and none could seed its edit form.
  * `save_mcp_server` unwraps the nested `server` object the UI sends; reading
    only a top-level `name` made adding a server impossible.
  * `list_mcp_servers` returns `transport`, `command` and `id` so a saved
    server does not come back looking blank.
  * `test_mcp_connection` reads the name out of the nested object; calling
    `as_str()` on it always produced `<unknown>`.
  * `check_dependencies` sends `detail`, but `ConfigurationTab` read `message`,
    so every diagnostics row rendered with no description.
  * `plugin_set_enabled` and `set_plugin_enabled` wrote to two disjoint stores,
    so the settings tab and the discovery view disagreed about every plugin.
    Both now go through `market::set_installed_enabled` /
    `market::installed_plugins` — the real `installed.json` record set.
  * `engine_status` gained the `initialize` block three call sites read
    (`version`, `codexHome`); 当前版本 showed 「—」 without it.
  * `test_connector` returned `{ok: true, detail: "stub probe"}` for a probe it
    never performed. It now reports the missing transport.

Failed turns rendered as successes
----------------------------------
`turn.error` and `turn.turnStatus` were written by the reducer and read by no
component, so a turn whose model call died rendered exactly like a completed
one. The header now says 「失败 · 用时 X 秒」 / 「已取消 · …」, marks the row with
the danger colour and a glyph, and shows the provider's own message underneath.

Browser-dev parity
------------------
The devbridge stub was diverging from the desktop on the same payloads: it
returned a `cwd` the desktop did not, and reported `ok: true` for a connector
probe. Both are aligned, so browser mode no longer masks these bugs.
