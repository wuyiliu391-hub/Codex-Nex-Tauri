ci: adopt the official Tauri GitHub Actions pipeline

Replaces my hand-written CI with the approach from the official guide
(https://v2.tauri.app/distribute/pipelines/github/), which uses off-the-shelf
actions instead of scripts maintained here.

What changed and why:

1. Build with tauri-apps/tauri-action@v1, not a hand-rolled cargo tauri build.
   The official action installs the correct Tauri CLI, runs the build, and can
   publish a release. This repo previously reimplemented the first two by hand
   (a CLI zip download + a stage-dist.ps1) and had no release step at all.

2. Drop sccache. The official pipeline uses Swatinem/rust-cache and
   dtolnay/rust-toolchain, and does not use sccache. sccache is effective but
   needs both SCCACHE_GHA_ENABLED and RUSTC_WRAPPER set correctly, and silently
   does nothing if either is wrong -- one more thing to get subtly wrong for no
   gain over the documented setup.

3. Fix a real caching bug: workspaces now points at ./src-tauri -> target.
   The official docs call this out for apps that are not at the repo root, which
   this one is not (frontend/ + src-tauri/). The previous workspaces: . cached
   the wrong directory and did nothing.

4. Fix a build-breaking config gap. tauri.conf.json had an empty
   beforeBuildCommand, so tauri build never built the frontend -- yet
   tauri::generate_context! embeds frontendDist (../frontend/dist) at compile
   time and that directory is gitignored. Every clean build would have failed.
   Now set to: npm --prefix ../frontend run build
   which is the official recommendation and keeps local and CI on one code path.

Jobs:
  checks  frontend typecheck+build; cargo test --lib (gates); fmt/clippy (report
          only, because this repo has never been run through cargo fmt and the
          author has no local Rust toolchain)
  build   tauri-action in build-only mode (no tagName/releaseName/releaseId)

Also verified while writing this: projectPath must stay unset. The official
guide defines it as the directory containing src-tauri/, i.e. the repo root
here; projectPath: src-tauri would make the action look for
src-tauri/src-tauri/.

Verified: no YAML tabs, no hand-rolled download steps, rust-cache path correct,
beforeBuildCommand resolves to an existing dir with a defined npm script, no
release inputs present, cargo test --lib ungated, both Cargo.toml parse,
tauri.conf.json parses, tsc --noEmit exits 0.
